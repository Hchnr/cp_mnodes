## 核验流水线

1. 新建 8,317 个互斥原始分区，12 节点、每节点 3 个元数据进程。
2. SSH 桥接断开后，扫描通过共享存储继续报告。SSH 失败不再被显示成零进度。
3. 对三个尾部大分区建立本机 24 路独立替代核验。保留原叶目录归属与全局边界掩码；
   原进程不停止，新旧哪份先完整就使用哪份，不能相加。
4. 替代分区只有在所有分片实际返回、SQLite 前沿无 pending/running、原始任务归属、
   子分区无重复及输入 SHA 校验通过后才能接管。原始计划和全部旧证据保留。
5. 对已结束的 missing/conflicts/errors 报告建立本地派生 SQLite 索引；
   逐路径去重后进行 24 路候选复核，校验计划与输出 SHA、记录数和覆盖集合。
6. 单独补查变化目录和访问异常。完成性审计、清单 SHA、规模阈值全部通过前不发数据任务。
7. `migration_reaudit_copy.py` 支持显式的远端执行或开发机回退执行。
   本机执行绑定 hostname 和 boot ID，不伪装成 12 个物理远端节点。
   普通文件继续采用 SHA256、目标读回、fsync、安全不覆盖发布及共享逐文件回执。
   缺失目录和链接独立计数，目录 inode 的大小不算成数据容量。

### 变化目录与自动衔接

`migration_reaudit_followup.py` 从全部已提交候选复核和原始枚举异常提取变化目录，
按真正的路径祖先关系去除重叠（不能只看排序后相邻项，`a-` 会插在 `a` 与 `a/b` 之间）。
69 个互斥范围分为 16 路递归补扫；报告必须位于控制目录的 `nodes/`，
否则底层安全检查拒绝启动。第一次不合规布局的失败记录保留，修正后的第二次启动
独立记录，不复用失败前沿，不冒称失败扫描已经产生观察。

补扫候选集合是“旧候选在该范围内的所有路径”与“新扫描发现”的并集，
不能只检查新发现，否则源删除后的旧缺失项会遗留。所有输入输出均绑定 SHA、
确切条数、进程启动身份和关库后页脚；本地 SQLite 前沿逐个验证没有未处理目录。

`migration_reaudit_close.py` 保留主复核不变，用独立覆盖层保存补扫后的最新观察。
持续变化的范围由 `migration_reaudit_capture.py` 进一步核验：

- 每个目录完整枚举前后的 inode、mtime、ctime 和名字集合必须一致；
  严格重开源路径，防止旧 FD 指向已被替换的目录却误报稳定。
- 目录内所有孩子都经过元数据检查；子目录继续递归，不能以“小叶目录”名义跳过子树。
- 捕获期间消失的路径要有 `source_disappeared` 观察，不能从统计里静默删掉。
- 有界重试仍不稳定、目录过大或访问失败时停止自动衔接，不能将门槛改成通过。

最终普通文件、目录和链接清单对主观察与覆盖层按路径替换、排序、去重，
容量仅累加普通文件逻辑字节。通过完整范围、异常闭合和严格小于 50 TB 校验后，
冻结 `final/final-report.json` 与 `conditional-copy-authorization.json`，
才准备两个独立补拷控制目录。桥接失效时明确记录开发机本地执行，不能声称使用了远端 12 节点。

监控同时显示变化范围扫描、候选复核、稳定核验、最终冻结基线和两个补拷作业。
已经终止的 worker 不再贡献历史速度；冻结基线不是已经写入量。

稳定捕获的一次性能故障发生在含约 1.86 万状态文件的 `sim_dispatch`：
原实现先顺序 `stat` 全部源条目，又在属性线程池中重复 `stat`，
把本来较短的核验窗口拉长，十次都遇到目录变更。去除冗余顺序阶段后，
实际同目录 2.50 秒、第二次尝试完成；保留完整名字集合、前后版本以及路径重开校验，
没有通过忽略 mtime/ctime 放宽门槛。
恢复控制器时从原始压缩输入与已验证捕获重建确切路径并集，
验证缓存集合完全一致，拒绝用“记录数变大了”代替断点续接证明。

## 复制期间的增量完整性收尾

最后大目录的原递归扫描已有 723,505 个结束目录，全部可与逐目录源版本对应。
`migration_reaudit_incremental_plan.py` 将这个基线冻结到混闪，并保留 58 个原始变化种子，
不能因父目录也变化就将所有种子折叠成一次整树重扫。

`migration_reaudit_incremental.py` 对每个种子捕获完整的直接孩子集合：

- 子目录在已结束基线中且源 inode/mode/mtime/ctime 一致时才复用旧观察窗口；
- 未知、被替换或版本变化的子目录加入检查队列；其他显式变化种子不能被跳过；
- 源目录消失或改成其他类型时保留祖先缺失/改型观察，不删除目标数据；
- 保留稳定前后版本、完整名字列表、所有孩子观察和整个队列决策的可重放日志。

运行侧实际在约 14 秒内完成 2,198 个目录、22,958 条观察，队列归零。
`migration_reaudit_incremental_verify.py` 使用同一冻结遍历实现重放全部决策，
验证种子没有遗漏、名字集合闭合、子目录没有跳过以及所有计数一致。
这不是把在线源说成同一时刻的快照；复用目录继续引用自己的原始观察窗口。

复核将新观察与两个在途冻结队列按相对路径比较：
8,217 个普通文件（1,801,036,805 字节）及 2,131 个目录属于不重叠新增范围；

### 本机目录搬运的锁竞争与恢复后的远端对照

桥接恢复后 12 个节点均通过 hostname、共享盘根 inode 和 CPU 配额检查。
本机目录进程的 `/proc/<pid>/task/*/wchan` 样本大多为
`rwsem_down_write_slowpath`；同期 382 个目标目录 FD 指向
`eai_pwm/datasets/_gl`。这提供了集中在同一个父目录上的本机锁竞争证据，
不是生产队列没有任务。不能据此推断所有等待都只有同一种原因。

`migration_namespace_profile.py` 在新的专用控制目录里复制同样的 32 个
空目录元数据，保留属性和 fsync，不搬运普通文件，也不改现有生产目标。
本机 O_RDONLY 对照约 2.21 秒；worker-0、worker-1 分别约 0.159、0.162 秒。
样本的源路径相同，但目标都是各自独立的实验目录，不等同于实际巨型父目录，
因此不能将这个比例直接当成全局提速比例。各自完整结果保存在：

```
final/namespace-profile-20261026T0540Z/
final/namespace-profile-remote-worker-0-v1/
final/namespace-profile-remote-worker-1-v1/
```

O_PATH 对照在两台远端分别约 0.195、0.196 秒，没有收益，未推广。
真正的远端接管需要先证明原进程已退出、全部在途任务排空，且回执恰好覆盖
已提交清单前缀；不能以恢复 SSH 为理由直接重复启动同一分片。
`migration_reaudit_handoff.py` 目前只提供前缀证据校验，不发信号、不启动 worker。

用户随后批准单分片对照，`migration_reaudit_handoff_runtime.py` 实施一次
namespace/worker-0 的主机交接。先在远端校验共享盘、原配置/授权/清单 SHA、
代码与目标 boot ID，再等待旧进程退出证明。控制器通过 pidfd 只向明确的旧进程
发送优雅排空信号；旧进程实际退出、所有在途任务落回执后，验证回执恰好覆盖
已提交前缀。新进程继承 43,506 条累计处理计数，只读取剩余任务，不重建已处理目录。
`migration_manifest_copy.worker` 新增可选 checkpoint，普通启动默认行为不变；
复制、属性、目标读回及 fsync 原语与原冻结代码完全一致，未启用 O_PATH。

真实任务 33 秒窗口内，试点约 133 项/秒，同期本机其他分片各约 2–3 项/秒。
这是单分片结果，不能乘以 12 当作全部扩展后的速度。

## 计量与边界

`migration_reaudit_attention_snapshot.py` 只提取打开日志时已可见的完整换行回执，
每次最多 64 个 `changed` 任务，并排除已处理快照的 ID；保存原行偏移与 SHA，
逐项绑定冻结分片中的 ID/相对路径/逻辑大小。半行和在途任务不进入补处理。
快照显式标记不是最终全量注意项清单；配合独立进程运行的一次性 retry helper，
原进程、原日志、原计数不动，同一路径不得当作额外唯一文件累计。

`migration_reaudit_attention_pass.py` 将其扩展成有限的串行收尾：每次最多 8 组、
每组仍最多 64 个已结束任务，仅一个子进程工作，复制并发保持 4。
通过前组 snapshot/manifest/plan 摘要绑定已接受新版本字节，后组在真正派发之前
将原始范围、全部前组和本组的新版本保守相加，必须严格小于 50 TB。
每组 helper 独立进程，避免多次安装复制引擎包装器；启动意图先独占落盘，
子进程异常不自动重启。一次源变化重试后仍不稳定的 ID 在该 pass 内不重复派发。
`identity_verified` 与 `copied` 分别计数：复制返回之后源仍可能立刻变化，
不能把 copied 当作最终身份稳定；没有全树完成结论。

- 所有权威计划、输入、日志、SHA 清单、回执和结果保存在混闪。
  `/tmp` 只保存可由这些证据重建的 SQLite 工作缓存和排他锁。
- 主枚举观察量、被替代分区的历史检查量、候选去重数、最终复核数和新写入量不能混为一谈。
- 同类型同大小的既有文件不等于内容已做 SHA 校验；全量内容哈希与硬链接拓扑不冒称完成。
- 源在线变化，因此报告记录观察窗口和动态项，不承诺整个树在同一瞬间的一致快照。
- `final-report.json` 应是补拷前冻结的核验快照；开始复制后不要改写它破坏授权摘要。
  后续复制结果使用独立的 post-copy 报告和回执。
