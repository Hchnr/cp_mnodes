## 清单与安全边界

权威输入：

```
/share-mixed/project/.hcr-readonly-audit-20261024-raw-excluded-72d05c/final/missing-files.jsonl.gz
SHA256: 4d1e2bae6c912b6d0923993c37510551d31502f8c14d8766953017ccd23359ac
```

准备阶段校验压缩清单 SHA、路径严格有序且唯一、文件类型、排除范围和精确数量/字节数。
按容量加每文件固定开销的权重生成 12 份互斥分片，文件和代码 SHA 均冻结在 `config.json`。
直接顺序读取分片喂给线程池，没有目录发现、中央发布瓶颈或空闲 HTTP 轮询。

复制沿用保守复制核心：源文件身份与核验时的 inode、size、mtime、ctime 必须一致；
祖先目录不跟随符号链接；临时文件计算 SHA256、目标读回验证、fsync 后通过不覆盖的硬链接发布。
现有目标只有内容校验相同才复用，其他情况记录冲突，不启用所有权覆盖模式。
源变化、源消失、目标冲突、读写错误均进入逐文件回执，不自动扩大到新的文件或版本。

## 断点与日志

`nodes/<node>/receipts-*.jsonl` 是混闪上的逐文件恢复证据；每约 3 秒 flush/fsync。
每次尝试新建回执文件，不修改旧回执，也不截断崩溃留下的半行。
恢复时重新核对成功回执的当前源/目标身份；证据仍有效的文件不再搬运。
发布后但回执落盘前发生崩溃时，下次通过现有文件的 SHA 校验复用，不盲目重写。
这是**文件级续传**，单个未发布大文件不承诺字节级续传。

本机 `/tmp` 仅有不含进度或清单的进程排他锁；清单、分片、启动记录、日志、回执、进度及冻结代码都在混闪。
节点 hostname 和两侧挂载身份均有启动门禁；同节点同任务由本地 flock 防止双启动。
不自动跨节点抢占分片；节点退出后应先确认旧实例确实退出，再制定恢复/重分配。

`stop.json` 是本轮独立的停止控制文件。创建有效 JSON 后，复制进程停止领取新文件并完成在途文件。
不得用恢复旧队列或 `SIGCONT` 旧进程的方式恢复本轮。
