# 复核和补传五分钟巡检

复核与补传巡检每 5 分钟检查控制器心跳、16 个节点的工作进程和挂载、异常、补传 outbox 以及 SwanLab 上报状态。复核、补传控制器及其守护进程继续负责工作领取、持久化和恢复；巡检不会因为容量入账低而单独重启它们。已有的 20 分钟速率口径不变，SwanLab 上报周期仍为 120 秒。

状态和历史位于复核运行目录的 `monitor20/status.json` 和 `monitor20/history.jsonl`。`windows.last_5m`、`last_20m`、`last_1h`、`last_6h` 分别包含实际采样秒数、文件及链接每小时、逻辑 TB 每小时和目录每小时。复核的逻辑 TB 是完成条目的元数据大小，不是存储或网络实际吞吐；目录工作完成时可能集中入账，短窗口可能波动很大。

完成百分比和剩余小时数使用历史文件索引及首轮复制、跳过容量作为参考，源端持续变化，这些值不是当前源的精确总量。历史参考用尽、速度为零、控制器状态过期或采样跨越控制器重启时，不输出该维度剩余时间；过期和跨重启窗口不会用于持续降速判断。

当文件和逻辑容量两个维度在两个连续五分钟窗口均低于参考窗口的四分之一时，巡检会标记 `sustained_decline_across_files_and_capacity`，并记录目录速率供进一步定位。参考窗口优先使用可比较的六小时样本，缺失时回退至一小时或二十分钟，避免持续降速过早被短窗口均值掩盖。这是性能提示，不是任务故障的证明，文件大小和目录结构变化也会影响速率。已有守护与巡检逻辑会在身份、心跳、备用守护及停止标记等条件均满足时恢复确认失联的控制器；无法安全确认原因时保留现场并标记异常。
