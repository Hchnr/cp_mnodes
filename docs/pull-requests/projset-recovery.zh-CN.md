# 为 projset 多节点复制增加自动恢复机制

开发容器或控制器退出后，即使共享日志和回执仍在，复制也可能停止。本次增加独立运行于 CPU 节点的守护与队列重建机制，使未确认任务能够续跑，并继续保留已有冲突目标。

## 变更

- 在 `cpu-master-0` 固定运行主控制器，`cpu-worker-0` 运行备用守护；支持互相拉起守护、节点本地排他锁、子进程监控及有间隔的重试。
- 重放租约前，根据主机、启动 ID、PID 启动时钟和命令身份隔离旧控制器及工作进程；无法隔离节点时等待恢复，避免并发写入。
- 从持久化任务、完成日志和所有恢复批次回执重建本地 SQLite 队列，保留乱序完成空洞、去重已发现路径，并复用有效回执以避免重复计数。
- 异常导出以回执路径和字节偏移标识记录，支持跨恢复批次增量读取并兼容旧检查点；节点健康及 OOM 诊断检查最新工作批次。
- 守护 SwanLab 和清单导出进程，沿用原实验、检查点及每 120 秒上报周期，补充恢复边界和人工启动文档。
- 删除两份已归档至 `docs/pull-requests/archive/` 的旧顶层 PR 说明，保留统一归档入口。

## 验证

- `python3 -S -B tools/repo.py test test_projset_copy test_projset_overview test_projset_usage test_projset_outcomes test_projset_recovery test_dataset_archives`：22 项测试通过。
- 源码目录复查：3 项恢复测试、2 项清单导出测试通过，覆盖日志重放、目标变化拒绝复用、进程身份隔离和跨批次导出幂等性。
- 411 个打包 Python 源文件语法检查通过，运行包文件名无冲突；`git diff --check` 通过。
- 已部署版本此前完成实机故障验证：终止主守护后，备用守护自动拉起主守护、隔离旧控制器，16 个 CPU 工作节点恢复。证据位置见 `docs/operations/projset-recovery.md`。

## 运行边界

已确认的冲突、源变化和文件级错误继续记录并留待人工处理；恢复不会覆盖目标或自动开启第二轮复制。两个守护所在容器同时退出时，由于没有系统开机服务，需要人工启动其中一个守护。主节点不可达不会触发跨主机控制器接管。在线源复制不构成时间点快照，目录元数据及硬链接拓扑仍需收尾。
